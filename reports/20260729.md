## 1. 요약 판정

SOKKANAEM은 현재 **핵심 아이디어와 희소 추론 구조가 검증된 후기 연구 프로토타입**이다.
정적 패치에서 Mamba hidden state를 정확히 보존하는 Δ-gating은 코드와 단위 테스트, 동일
마스크의 token-drop 대조 실험으로 뒷받침된다. 최신 v8 계열은 기존 구조의 높은 dense 연산
바닥도 크게 낮췄으며, 실촬 실내 홀드아웃에서는 v7보다 깊이 정확도가 뚜렷하게 개선됐다.

다만 다음 이유로 아직 배포 또는 논문화 완료 단계는 아니다.

1. 최신 후보 `arm2-binloss`는 최종 레시피로 처음부터 장기 학습한 모델이 아니라,
   teacher를 사용해 60k step 학습한 v8에서 teacher를 끄고 bin CE를 추가해 8k step
   회복 학습한 체크포인트다.
2. 최신 합성 500클립 평가는 멀티데이터셋 혼합이 아니라 실제로 VKITTI2만 포함한다.
3. 최신 v8/arm2의 실제 FPS·latency·peak VRAM·전력 측정이 없다.
4. 현재 기본 추론 명령은 체크포인트의 spatial cache 설정을 꺼 버려 의도한 희소 경로를
   사용하지 않는다.
5. Triton block-sparse kernel과 Jetson Orin 검증은 미착수다.

따라서 현재 위치는 다음과 같다.

| 영역 | 상태 | 판정 |
|---|---|---|
| 핵심 수학과 PoC | 완료 | 강함 |
| 학습·평가 파이프라인 | 구현 완료 | 프로토콜 보강 필요 |
| 실촬 실내 정확도 | 유망 | 최신 후보 재학습 필요 |
| 합성·원거리 정확도 | 혼합 결과 | 미해결 |
| MAC 효율 | 개선 확인 | 해석적 수치 |
| 실제 시스템 가속 | 미완료 | 핵심 공백 |
| 재현성 | 부분 확보 | seed·effective config·산출물 보존 필요 |
| 논문화 | 초안 존재 | 최신 결과와 참고문헌 반영 필요 |

## 2. 저장소와 코드 상태

보고서 작성 직전 worktree는 깨끗했고, 최신 커밋은 다음과 같다.

```text
2bc4bc0 2026-07-28 feat: bin-distribution supervision; drop the teacher term it exposed as harmful
```

프로젝트 전용 Conda 환경에서 전체 테스트를 재실행한 결과:

```text
53 passed in 6.16s
```

테스트는 다음 핵심 계약을 포함한다.

- mask=0에서 temporal SSM hidden state의 bit-exact 복사
- 동일 프레임에서 active ratio 0%와 안정적인 depth
- 다중 스트림 state 독립성
- Δ-gating과 token drop의 상태 동결 동등성
- spatial/temporal cache의 학습 경로와 gradient
- 4방향 cross-scan 순열과 수직 이웃 처리
- DPT decoder, bin head, bin CE loss
- GMC 정렬과 feature gating
- 데이터 정렬·증강·손상 프레임 방어
- OPW/TCE를 포함한 시간 지표

현재 테스트 건강도는 좋지만 CI 설정과 GPU 성능 회귀 테스트는 없다. 테스트 통과는 수학적·기능적
계약의 신뢰도를 높이지만 최신 sparse 경로의 실제 GPU 속도를 보장하지는 않는다.

## 3. 현재 주력 구조

최신 설정은 [`configs/main_v8.toml`](../configs/main_v8.toml)이다.

### 3.1 모델 구성

- 입력 학습 해상도: 256×256
- 패치 크기: 16×16
- 토큰 수: 16×16 = 256
- hidden dimension: 192
- backbone depth: 4
- temporal/spatial 블록: T-S-T-S 교차 구성
- SSM state dimension: 16
- 공간 스캔: 4방향 raster/column-major cross-scan
- local branch: depthwise 3×3 convolution 2층
- decoder: RGB stem skip을 사용하는 DPT형 다중스케일 융합
- depth head: 64개 학습형 log-depth bin의 expectation
- detector: MSE, hysteresis, 1패치 dilation, 30프레임 keyframe
- sparse path: `spatial_cache=true`, `temporal_cache=true`

### 3.2 모델 크기

체크포인트를 직접 로드해 계산한 결과:

| 체크포인트 | step | 파라미터 | 파일 크기 |
|---|---:|---:|---:|
| `main_v7/latest.pt` | 15,000 | 2,796,033 | 44.85MB |
| `main_v8/latest.pt` | 60,000 | 4,185,872 | 67.20MB |
| `arm2-binloss/latest.pt` | 8,000 | 4,185,872 | 67.20MB |

최신 모델의 순수 FP32 가중치는 약 16.7MB다. 67.2MB 체크포인트에는 raw model, EMA,
optimizer state 등이 함께 들어 있다.

### 3.3 현재 학습 레시피

현재 `main_v8.toml`은 다음 손실을 사용한다.

```text
SI-log
+ 0.5 × single-scale gradient
+ 0.1 × temporal consistency
+ 0.05 × pseudo-normal
+ 0.5 × multi-scale disparity gradient
+ 0.2 × bin cross-entropy
```

teacher 출력 증류는 3-arm 실험에서 제거됐다. 현재 데이터는 TUM, Bonn, VKITTI2,
TartanAir v2, PointOdyssey의 5소스 혼합이며, 학습 sampler가 데이터셋별 추출 확률을
균등화한다. 클립 길이는 4, batch는 4, 최종 random skip 학습률은 50%다.

## 4. 학습 체크포인트의 실제 계보

현재 결과를 해석할 때 다음 계보를 구분해야 한다.

1. **v3**: 합성 3소스, 100k step, 2.8M. 상수 붕괴를 수정한 첫 정상 본 학습.
2. **v7**: v3 EMA에서 시작해 실촬 2소스와 합성 3소스를 15k step 파인튜닝.
3. **v8**: v7 EMA를 부분 로드하고 4방향 scan, local conv, DPT decoder, bins,
   spatial/temporal cache, DA v2 teacher를 넣어 60k step 학습.
4. **arm0**: v8에서 같은 처치로 8k step 추가 학습한 대조군.
5. **arm1**: v8에서 teacher를 끄고 8k step 추가 학습.
6. **arm2**: v8에서 teacher를 끄고 bin CE를 추가해 8k step 추가 학습.

현재 가장 좋은 실촬 결과는 arm2지만, arm2는 teacher의 영향을 전혀 받지 않은 모델이 아니다.
60k step 동안 teacher를 사용한 v8에서 8k step 동안 그 영향을 되돌린 모델이다.

또한 중단된 dim=384 v5 실행은 train log상 step 45,350 부근에서 종료됐고 마지막 저장
체크포인트는 step 44,000이다. 이 경로는 v7/v8로 우선순위가 전환되면서 사실상 보류됐다.

### 5.2 실촬 성능 해석

arm2는 v7 대비:

- AbsRel: 0.1789 → 0.1386, 약 **22.5% 감소**
- RMSE: 0.6173 → 0.5349, 약 **13.3% 감소**
- δ1: 0.7902 → 0.8472, **+5.7%p**
- active ratio: 동일하게 17.9%, 즉 평균 82.1% 패치가 갱신되지 않음

실촬 홀드아웃은 총 488클립 중 GT가 없는 1개를 제외한 487클립이다. 구성은 TUM holdout
89클립과 Bonn holdout 399클립이며, 학습에 사용하지 않은 시퀀스를 평가한다. 다만 같은
TUM/Bonn 데이터셋의 다른 시퀀스는 학습에 포함됐으므로 이는 외부 도메인 zero-shot이 아니라
**동일 데이터셋 계열의 sequence holdout 성능**이다.

bin CE는 arm1 대비 arm2의 실촬 AbsRel을 약 6.5% 낮추고 δ1을 0.67%p 높였다. 반면 OPW와
TCE는 소폭 후퇴했다. 정확도와 시간 변화 추종 사이에 작은 trade-off가 존재한다.

### 5.3 합성 성능 해석

arm2는 v7 대비:

- AbsRel: 0.2895 → 0.2735, 약 **5.5% 개선**
- δ1: 0.5923 → 0.5898, **-0.25%p**로 사실상 동일
- RMSE: 31.77 → 38.49, 약 **21.2% 악화**
- t-delta: 0.1591 → 0.2010, 약 **26.3% 악화**
- TCE: 0.0251 → 0.0273, 약 **8.8% 악화**

즉 arm2가 v7을 전면적으로 이기지는 않는다. 근거리·상대 오차는 개선됐지만 원거리 큰 오차와
시간 안정성이 후퇴했다. TartanAir의 0.5–129m 범위와 64개 전역 log-depth bin의 원거리
해상도 부족이 후보 원인이지만, 최신 500클립 평가는 실제로 TartanAir를 포함하지 않으므로
소스별 재평가가 필요하다.

### 5.4 정성 결과

[`outputs/v8/`](../outputs/v8/)과 [`outputs/arm2-binloss/`](../outputs/arm2-binloss/)에
각 10개의 RGB | 예측 | GT 패널이 있다.

문서에 기록된 진단은 다음과 같다.

- 전역 배치와 대략적인 깊이 순서는 맞는다.
- 사람, 의자, 기둥 등 전경 물체의 정확한 depth가 살아나지 않는다.
- 예측의 공간 gradient 크기는 16px oracle과 비슷하므로 단순히 출력이 너무 매끄러운 문제가 아니다.
- 같은 클립에서 모델이 32px 블록 상수 oracle보다도 나쁘므로 현재 병목은 명목 패치 해상도보다
  **표현 품질과 값 배치 정확도**다.

### 5.5 외부 모델 대비

외부 baseline과의 공통 1,000클립 비교는 최신 arm2가 아니라 v3로 수행됐다.

| 모델 | 파라미터 | AbsRel ↓ | RMSE ↓ | δ1 ↑ | t-delta ↓ | OPW ↓ | TCE ↓ |
|---|---:|---:|---:|---:|---:|---:|---:|
| SOKKANAEM v3 | 2.8M | 0.4292 | 26.57 | 0.5285 | **0.2455** | 0.0541 | 0.0879 |
| Depth Anything V2 Small | 24.8M | 0.5802 | 62.32 | **0.7494** | 9.4742 | 0.2458 | 0.2616 |

이 표가 지지하는 범위는 제한적이다.

- SOKKANAEM은 원시 프레임 출력 변화인 t-delta에서 가장 안정적이다.
- 그러나 DA3는 OPW와 TCE가 더 좋고, VDA도 TCE가 SOKKANAEM보다 좋다.
- 따라서 기여는 “시간 일관성 전반의 우위”가 아니라 **후처리 없는 원시 플리커 억제**로

- 최신 arm2는 외부 baseline과 공통 표본으로 다시 평가되지 않았다.

## 6. 효율성

### 6.1 해석적 MAC

[`scripts/flops.py`](../scripts/flops.py)를 재실행한 결과다.

#### 기존 v7 구조

| active | Δ-gating만 | +spatial cache | +두 cache |
|---:|---:|---:|---:|
| 100% | 2.337 GMAC | 2.337 GMAC | 2.337 GMAC |
| 16.6% | 2.266 GMAC, 97.0% | 1.841 GMAC, 78.8% | 1.742 GMAC, 74.5% |
| 0% | 2.252 GMAC, 96.4% | 1.743 GMAC, 74.6% | 1.623 GMAC, 69.4% |

기존 구조에서는 Δ-gating만으로는 총연산이 거의 줄지 않았다. decoder가 67.8%를 차지하고,
정적 temporal 토큰도 active 토큰 비용의 58.5%에 해당하는 projection/readout을 계속
계산하기 때문이다.

#### 최신 v8/arm2 구조

| active | Δ-gating만 | +spatial cache | +두 cache |
|---:|---:|---:|---:|
| 100% | 1.644 GMAC | 1.644 GMAC | 1.644 GMAC |
| 16.6% | 1.573 GMAC, 95.7% | 0.723 GMAC, 44.0% | **0.623 GMAC, 37.9%** |
| 0% | 1.559 GMAC, 94.8% | 0.539 GMAC, 32.8% | **0.420 GMAC, 25.5%** |

최신 실측 active ratio에 대입하면:

| 평가 active | 두 cache 사용 | 풀연산 대비 |
|---:|---:|---:|
| 15.4% | 0.608 GMAC | **37.0%** |
| 17.9% | 0.639 GMAC | **38.9%** |

full compute 자체도 v7 2.337 GMAC에서 v8 1.644 GMAC로 약 29.7% 감소했다. dense 바닥은
embed 2.3%, DPT decoder 23.1%, local branch 약 0.1%다.

### 6.2 exactness의 범위

효율 수치는 다음 세 메커니즘을 구분해야 한다.

1. **Δ-gating state transition**: exact. mask=0이면 hidden state가 bit-identical하게 복사된다.
2. **temporal output cache**: approximate. 작은 입력 변화가 있어도 이전 block 출력을 재사용한다.
3. **spatial output cache**: approximate. 정적 토큰의 새로운 공간 문맥 기여를 생략하고 이전
   출력을 재사용한다.

따라서 “정적 패치 state 보존이 exact”라는 주장은 유효하지만, 최신 모델의 37–39% MAC 경로가
전체적으로 exact하다고 표현하면 안 된다. 큰 종단 절감은 학습된 근사 캐시까지 함께 사용한 결과다.

### 6.3 실제 속도 상태

기존 모델에서 기록된 RTX 4090 wall-clock 결과:

- 128px sequential scan: 104 FPS
- 128px chunked segment-sum scan: 372 FPS
- 128px full-compute CUDA graph: 1,075 FPS
- 256px full-compute CUDA graph: 366 FPS
- 256px 정적 스트림 + cache: 460 FPS

이 수치는 최신 v8/arm2가 아니라 주로 기존 2.8M 구조에서 측정한 값이다. 최신 모델은
4방향 scan과 DPT decoder, 두 cache를 사용하므로 이 FPS를 그대로 인용할 수 없다.

RTX 4090에서는 기존 모델이 kernel launch-bound라 MAC 감소가 FPS로 직접 이어지지 않았다.
최신 모델의 다음 항목은 아직 측정되지 않았다.

- FP16/eager/compile별 latency와 FPS
- cache on/off 및 active ratio별 wall-clock 곡선
- peak VRAM
- 장기 스트림의 안정된 평균
- 멀티스트림 처리량
- Jetson Orin latency와 energy/frame

### 6.4 스트림 state 메모리

256px, batch 1, dim 192 기준으로 temporal hidden state, spatial/temporal cache, 이전 프레임,
detector mask를 합산한 이론적 영속 state는 스트림당 약:

- FP32: **14.16MB**
- FP16: **7.08MB**

이는 peak runtime VRAM이 아니라 프레임 사이에 유지되는 state의 구조적 크기다. 해상도와
스트림 수에 거의 선형으로 증가하므로 멀티스트림 edge 배포에서는 모델 가중치만큼 중요한
효율 지표다.

## 7. 평가 프로토콜 감사

### 7.1 합성 first-N 표본 편향

평가 코드는 `build_mixed()`가 반환한 `ConcatDataset`을 `shuffle=False`로 순서대로 읽고,
`max_clips`에서 중단한다. 현재 합성 holdout의 소스별 길이는 다음과 같다.

| 소스 | holdout 클립 |
|---|---:|
| VKITTI2 | 660 |
| TartanAir v2 | 284 |
| PointOdyssey | 7,985 |
| 합계 | 8,929 |

그 결과:

- first 500 = VKITTI2 500클립
- first 1,000 = VKITTI2 660 + TartanAir 284 + PointOdyssey 56
- 전체 8,929에서는 PointOdyssey가 89.4%를 차지

따라서 REPORT의 “합성 500클립” 최신 표는 **VKITTI2 500클립**으로 이름을 좁혀야 한다.
1,000클립 표도 동일 모델 간 비교에는 재현 가능하지만 멀티도메인 대표 표본은 아니다.

필요한 수정은 소스별 정량표를 기본으로 보고하고, 통합 수치는 데이터셋 균등 표본 또는 명시적인
가중 평균으로 계산하는 것이다.

### 7.2 median scaling

`scripts/eval.py`는 각 클립의 예측을 GT median에 맞춘 후 AbsRel, RMSE, δ1을 계산한다.
따라서 현재 수치는 상대 깊이 구조를 평가하며 다음을 검증하지 않는다.

- 절대 metric scale
- 카메라별 scale calibration
- 장기 스트림에서 scale drift

고정 CCTV에서 실제 거리 단위가 필요하다면 unscaled metric 지표와 scale drift를 별도로
보고해야 한다.

### 7.3 시간 지표

- t-delta는 상수 출력이 전역 최적이라 단독으로 신뢰할 수 없다.
- OPW도 공간 상수 필드에는 0이 될 수 있다.
- TCE는 예측 warp residual과 GT residual의 차이를 측정해 상수 출력을 벌점한다.
- 현재 flow mask에는 in-bounds와 GT validity만 있고 forward-backward occlusion 검사는 없다.
- pose 기반 TAE는 카메라 intrinsics/extrinsics 배관이 없어 미구현이다.

현재처럼 정확도, t-delta, OPW, TCE, constant control을 함께 읽는 방향은 타당하다.

### 7.4 통계적 신뢰도

3-arm 학습은 같은 초기 체크포인트를 사용했지만 코드에 고정 seed 옵션이 없고 반복 seed도 없다.
따라서 sampler 순서, 데이터 증강, random mask가 arm마다 달라질 수 있다. teacher 제거 효과는
크기가 커서 강한 신호지만, bin CE의 비교적 작은 차이는 seed variance를 분리하지 못했다.

최종 주장에는 최소 3개 seed의 평균과 신뢰구간 또는 표준편차가 필요하다.

## 8. 추론·재현성 통합 문제

### 8.1 기본 추론이 spatial cache를 끄는 문제

현재 `scripts/infer.py`는 다음 값을 항상 override로 전달한다.

```python
kw = {"gmc": args.gmc, "spatial_cache": args.spatial_cache}
```

`--spatial-cache`의 기본값이 `False`이므로 `from_checkpoint()`가 `main_v8.toml`에서 읽은
`spatial_cache=true`를 기본 실행이 다시 `False`로 덮어쓴다.

최신 active ratio에서 temporal cache만 남기고 spatial cache를 끄면 해석적 MAC은:

| active | 현재 기본 infer 경로 | 풀연산 대비 |
|---:|---:|---:|
| 15.4% | 1.471 GMAC | 89.5% |
| 17.9% | 1.476 GMAC | 89.8% |

의도한 두-cache 경로의 37.0–38.9%와 큰 차이다. 현재는 명령에 `--spatial-cache`를 반드시
명시해야 한다. 더 안전한 수정은 boolean override를 사용자가 명시했을 때만 전달하도록
CLI를 삼상태로 바꾸는 것이다.

### 8.2 추론 해상도 기본값

`infer.py`의 기본 `--size`는 128이고, `from_checkpoint()`는 sidecar TOML의 `[model]`만
복원한다. top-level 학습 크기 256은 자동 복원되지 않는다. 최신 체크포인트를 README의
기본 명령으로 실행하면 학습·평가 해상도와 다른 128px로 추론한다.

checkpoint에 input size를 포함하거나, inference가 top-level config까지 읽도록 해야 한다.

### 8.3 effective config 미보존

학습 스크립트는 사용자가 지정한 원본 TOML을 work directory에 그대로 복사한다. CLI override로
바뀐 최종 인자는 기록하지 않는다. 그 결과 `arm1-noteacher/config.toml`과
`arm2-binloss/config.toml`에는 실제 실행과 달리 `teacher_weight=0.5`가 남아 있다.

체크포인트도 model, optimizer, step, EMA, 일부 외부 loss state만 저장하며 다음은 없다.

- 병합된 최종 인자
- 실제 실행 명령
- random seed
- Git commit
- PyTorch/CUDA/cuDNN 버전
- 데이터셋 파일 목록 또는 manifest hash

현재 arm 결과는 콘솔 로그의 구간 제목과 실험 문서에 의존해야 재구성할 수 있다.

### 8.4 산출물 보존

`.gitignore`가 `work_dirs/`와 모든 체크포인트를 제외한다. 코드 저장소를 복제해도 다음 핵심
근거는 복원되지 않는다.

- 학습 체크포인트
- train/eval 원본 로그
- per-clip score JSON
- 3-arm 설정 복사본

대용량 가중치를 Git에 직접 넣을 필요는 없지만, release asset 또는 artifact storage와 함께
체크섬, effective config, metric summary를 버전 관리해야 한다.

## 12. 최종 결론

SOKKANAEM의 가장 강한 결과는 다음 세 가지다.

1. 정적 패치의 Δ-gated temporal state가 정확히 보존되며, 동일 마스크의 token drop보다
   깊이 정확도와 안정성이 압도적으로 좋다.
2. 실촬 실내 holdout에서 약 82%의 패치 업데이트를 억제하면서 arm2가 AbsRel 0.1386,
   δ1 0.8472를 달성했다.
3. v8 구조는 full compute를 2.337에서 1.644 GMAC로 낮추고, 두 cache를 사용할 때
   현재 active ratio에서 약 37–39%의 해석적 MAC까지 내려간다.

가장 큰 공백은 이 MAC 절감이 최신 모델의 실제 latency·energy 절감으로 이어진다는 증거가
없다는 점과, 최신 합성 평가가 멀티도메인을 대표하지 않는다는 점이다. 또한 현재 최선
체크포인트는 최종 레시피의 장기 학습본이 아니다.

따라서 다음 마일스톤은 새로운 기능 추가보다 **평가 protocol 정정 → teacher-free 장기 학습 →
최신 wall-clock/edge 측정** 순서가 적절하다. 이 세 단계가 완료되면 SOKKANAEM은 연구
프로토타입에서 논문화 가능한 재현 실험과 실제 시스템 후보로 넘어갈 수 있다.
