# 깊이 수정 없는 학습형 Q0 전체 갱신 정책

2026-09-09. [국소 출력 보정](Q0_REGION_REPAIR_STUDY_20260909.md)의 후속.

후속: [흐름 계산 전 RGB 판단](Q0_PREFLOW_SCHEDULING_STUDY_20260909.md)에서 비용을 분리했다.
MLP q50은 두 개발 구간과 시작점 변경 품질을 통과하고 반복 측정에서 K2보다 빨랐다.
아래는 기존 20입력·흐름 계산 후 판단 실험의 결과이며 그대로 보존한다.

**SSM 상태 유지·초기화·MLP 정책을 각각 학습하고, training 내부에서 정한3개 임계값으로 평가했다.
두 개발 구간의 품질을 함께 지키는 정책은 있었지만, 기존 K2 출력-flow보다 느렸다.**
빠른 정책은 한쪽 개발 구간에서 품질을 지키지 못했다. 새 정책은 개선 모델로 채택하지 않는다.
SSM은 더 이상 깊이값을 수정하지 않고 Q0 전체 갱신 시점만 결정한다.

## 1. 이전 갱신 예측과 다른 점

이전 `qrisk_study`는 Q0 특징을 SSM으로 보정할 때 생기는 오차를 예측했다.
이번에는 이미 품질 기준을 통과한 **출력-flow K2를 K4까지 연장할 수 있는지**를 판단한다.

- 전체 갱신 직후 첫 프레임(gap1)은 항상 flow-only로 출력한다.
- Gap2/3에서 예상 위험이 임계값보다 낮으면 재사용하고, 높으면 전체 Q0를 실행한다.
- Gap4는 무조건 전체 갱신한다. 연속 생략은 최대3프레임이다.
- 생략 출력은 이전 깊이의 nearest 흐름 이동 그대로다. 학습 모듈이 깊이를 보정하지 않는다.
- 정책 h는 gap1에서도 업데이트하여 gap2/3 판단에 전달한다. 전체 갱신하면 h를 초기화한다.
- 이 규칙은 갱신 간격만 K2–K4로 제한한다. 임의의 영상에서 K2 품질을 보장하는 규칙은 아니다.

입력은 현재/anchor RGB 통계14개와 불확실 비율·흐름 크기 평균/95분위·RGB 대응 잔차·
후보 log-depth gradient/std6개, 총20개다. 현재 teacher/GT는 추론 입력에 없다.
후보 흐름과 통계를 먼저 계산하므로 **재사용을 거절하더라도 그 계산 비용을 이미 지불한다**.

## 2. 학습과 임계값 결정

| 구성 | 구조 | 파라미터 | 학습 |
|---|---|---:|---|
| Carry SSM | 20→16, SSM16/state4, risk head | 1,689 | h 유지 |
| Reset SSM | 위와 동일 | 1,689 | 매 입력 h0 |
| MLP | 같은 입·출력 경로,16→39→16 | 1,688 | 비순환 |

- Seed741, 같은 공통 초기 가중치·batch 순서·손실. 각1,000 optimizer step, batch32, AdamW lr.001.
  Carry/Reset은 동일 초기 SSM 가중치다. MLP는 core 함수가 다르므로 초기 출력까지 동일한 대조는 아니다.
- 기존 training192개4프레임 클립의 첫48개/source(144클립)는 fit, 나머지16개/source(48클립)는 임계값 설정용으로 사용했다.
  두 부분 및 개발 자료 사이의 프레임 경로 교집합0, reserved final sequence 제외를 확인했다.
- 클립의 anchor0/1 각각에서 가능한 흐름 재사용 prefix를 만들었다. 총384 trace/960 observation,
  fit288 trace/720 observation, 임계값용96 trace/240 observation이다.
  Gap2/3의 임계값 설정용 관측은144개다.
- 라벨은 실제 flow 후보와 현재 Q0의 `log-depth L1 +2×multiscale log-gradient L1`이다.
  이는 **위험 proxy**이지 GT 품질 gate의 모든 지표를 예측하는 라벨은 아니다.
- 입력 정규화 통계는 fit 부분만으로 계산했다.
- 각 모델에서 임계값용 gap2/3 **예측값의25/50/75분위수**를 적용했다.
  같은 명목상 수용 비율 규칙이지만 모델별 수치 임계값은 다르다.
- 임계값 파일은 개발 평가 전에 저장했다. 개발 결과를 보고 수치를 조정하지 않았다.
  원래 training 일부를 사용한 설정이며 독립 장면 검증이나 확률적 안전성 보장이 아니다.

| 모델 | q25 | q50 | q75 | 임계값용 자료 MAE |
|---|---:|---:|---:|---:|
| Carry SSM | .035557 | .054953 | .071618 | .015365 |
| Reset SSM | .033537 | .052792 | .071405 | .015240 |
| MLP | .030879 | .048026 | .073400 | .016109 |

해당 자료의 실제 proxy 평균은 .050978이다. 이 MAE만으로 미래 오류 상한이나 위험 확률을 주장하지 않는다.

## 3. 개발 결과

품질 gate는 기존 Q0 대비 raw/edge AbsRel·overshoot·flat-TV 각+1% 이내,
경계F1 감소≤.005, source별 raw+2% 이내를 모두 요구한다. Dense 대비 시간 감소≥5% 기준도 유지한다.
새 연구의 개선 여부는 이 기준뿐 아니라 **이미 통과한 output-flow K2와의 비교**로 판단한다.

| 정책 | L32 품질 | L256 품질 | L256 생략 비율 | L256 평균 ms¹ | K2 대비 시간 변화 |
|---|---|---|---:|---:|---:|
| Q0 dense | 기준 | 기준 | 0% | 7.535 | — |
| Output-flow K2 | 통과 | 통과 | 50.00% | 4.393 | 기준 |
| Output-flow K4 | 실패 | 실패 | 75.00% | 2.691 | −38.75% |
| Carry q25 | 통과 | 통과 | 53.52% | 5.238 | +19.22% |
| Carry q50 | 실패 | 통과 | 64.06% | 4.278 | −2.63% |
| Carry q75 | 실패 | 실패 | 70.02% | 3.731 | −15.07% |
| Reset q25 | 통과 | 통과 | 52.93% | 5.282 | +20.24% |
| Reset q50 | 실패 | 통과 | 62.30% | 4.429 | +0.82% |
| Reset q75 | 통과 | 실패 | 69.63% | 3.766 | −14.27% |
| MLP q25 | 통과 | 통과 | 53.03% | 5.170 | +17.68% |
| MLP q50 | 실패 | 실패 | 59.08% | 4.626 | +5.30% |
| MLP q75 | 실패 | 실패 | 70.02% | 3.628 | −17.43% |
| Carry q50 같은 가중치/h 제거 | 실패 | 통과 | 63.67% | 4.307 | −1.96% |

¹ 단일 RTX4090 동기화 GPU-resident 프레임 호출 시간이다. CPU 흐름·전송·통계·정책·Q0·telemetry 포함,
최초 IO/H2D·영상 decode 제외. 다른 GPU 프로세스가 존재한다.
작은 시간 차이의 유의성 또는 Pi4/Nano 실기기 가속을 주장하지 않는다.

세 q25 정책은 모두 두 개발 구간에서 품질과 dense 대비 가속 기준을 통과한다.
그러나 L256에서 K2보다17.68–20.24% 느려 **현재 대조군을 개선한 것은 아니다**.

Carry q50은 L256 raw .159751, 경계F1 .620857, flat-TV+.586%로 통과하지만,
L32 flat-TV+1.621%로 실패했다. Reset q75는 반대로 L32는 통과하지만 L256 edge/flat 제한을 넘었다.
MLP q50의 L256 flat-TV+1.0092%도 정해진+1%를 넘으므로 반올림해 통과로 바꾸지 않았다.

## 4. 판단이 일부 작동해도 빨라지지 않은 이유

Carry q25의 L256에서 실제 Q0 호출은512→476회로36회 줄었다.
그러나 재사용을 검토하다 위험하다고 판단해 Q0를 실행한 프레임이443회였다.

| Carry q25, L256 실제 실행 사유 | 횟수 | 해당 프레임 평균 ms |
|---|---:|---:|
| 클립 첫 전체 갱신 | 4 | 7.747 |
| 갱신 직후 필수 생략 | 474 | 1.839 |
| 위험 판단 후 전체 갱신 | 443 | 9.272 |
| 추가 재사용 허용 | 74 | 1.794 |
| 최대 간격 강제 갱신 | 29 | 7.610 |

이 표는 같은 프레임의 비용을 인과적으로 분해한 benchmark가 아니라, 원래 측정값을 사유별로 묶은 것이다.
그럼에도 거절된 재사용에서 흐름·정책 비용과 Q0 비용을 모두 지불하는 실행 구조는 명확하다.
모델이 작아도 전체 판단 경로가 저렴한 것은 아니다.

위험 순위 자체가 전혀 무의미했던 것은 아니다. Carry q25가 L256에서 추가 재사용한 후보의
실제 Q0 proxy 평균은 .033462, 거절한 후보는 .076216이었다.
다만 개발의 확장 판단 시점 MAE는 .023269로, training 내부 임계값 자료 MAE보다 컸다.
또한 평균 depth/gradient proxy는 기존 gate의 flat-TV·source별 손상 등을 직접 제약하지 않는다.

## 5. SSM 기억 기여와 출력 검증

같은 Carry q50 가중치에서 h만 제거하면 전체 갱신 여부가 L32 2곳, L256 178곳에서 바뀌었다.
L256의 전체 호출 수 차이는4회뿐이다. 한 결정이 다음 갱신 위상·캐시·미래 판단까지 바꾸므로
이는 정책 전체의 개입 효과이며178개 독립적인 기억 개선 사례가 아니다.

L256에서 기억 유지/제거 둘 다 품질 통과, L32에서는 둘 다 flat 기준 실패였다.
상태를 유지한 결과가 모든 정확도·경계·속도에서 일관되게 우월하지 않으므로 SSM 고유 이득은 미입증이다.

- 관련 회귀 테스트 **96 passed**.
- 실제 전체 갱신5,780회에서 해당 dense Q0와 출력 차이0.
- 학습 정책의 생략7,980회에서 이전 출력으로 흐름을 다시 계산해 저장된 출력과 차이0 확인.
  깊이값을 별도로 수정하지 않는다는 계약을 확인했다.
- 최대 gap4 강제 갱신, gap1 필수 생략, gap2/3 임계값 결정, h reset·caller cache 비변경을 검사했다.
- 각 모델의144개 training 내부 관측으로 임계값을 다시 계산해 저장값과 정확히 동일함을 확인했다.
- 실행 source·Q0·training/development/cache hash 계약 검사 통과.
- 기존 모델·통과 후보·원고·reserved final 평가 결과는 수정하지 않았다.

## 6. 결정과 다음 우선순위

**추가 생략 판단은 구현·학습·감사했지만, 기존 K2를 대체할 정책은 확보하지 못했다.**
두 개발 구간을 함께 통과한 K2를 기준 대조군으로 계속 유지한다.
이번 구간별 결과에 맞춰 임계값을 미세 조정하거나 품질 허용치를 늘리지 않는다.

다음 작업의 우선순위는 다음과 같다.

1. 흐름 계산을 한 뒤 거절하는 비용을 줄이도록, 더 저렴한 사전 판단 경로와 기존 정책을 비교한다.
   우선 기존 실행의 총비용을 줄일 수 있는지 확인하고 작은 risk core의 파라미터 수만 최적화하지 않는다.
2. Training 자료에서 평균 오류 하나뿐 아니라 경계/flat 손상을 구분하는 위험 목표를 검증한다.
   Threshold는 training 내부에서 고정하고 동일한 개발 gate를 유지한다.
3. SSM 상태 유무와 MLP 대조를 유지하며, 고유 이득이 없으면 기억 모듈을 추가 성과로 주장하지 않는다.
4. 새 정책보다 먼저 검증된 K2의 독립 장면·다른 움직임·반복 지연·실기기 확대가 필요한 상황도 함께 고려한다.
